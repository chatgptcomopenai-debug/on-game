# «Избранный»: итоговый план реализации

## 0. Что должно быть весело и честно
- **Читаемость.** Кто Избранный, видно за 0,3 с: обводка ×1,6, пульсирующая аура цвета силы, стрелка-указатель у края экрана. Каждой атаке Избранного предшествует телеграф (контур зоны поражения, 300–500 мс).
- **Контригра.** У каждой силы есть слабость и окно уязвимости. У охотника всегда есть рывок с i-frames.
- **Камбэк.** Отстающему охотнику даём небольшой бонус к урону, за урон по Избранному начисляются очки-ассисты.
- **Короткие сессии.** Матч длится 5×90 с, около 9 минут. Вход по коду, без регистрации.

## 1. Сеть: P2P, звезда, авторитетный хост (PeerJS)
- Брокер — бесплатный `0.peerjs.com`, адрес задаётся в конфиге (запасной вариант — свой PeerServer на Render/Fly). Хост — создатель комнаты. Код из **5 символов** (A–Z и 2–9, без I/O/0/1), peerId хоста = `izb-<КОД>`. Клиенты соединяются только с хостом.
- Два DataChannel: `reliable:false, ordered:false` для ввода и снапшотов; reliable для событий (смерть, смена Избранного, раунд, лобби).
- **NAT.** STUN Google и бесплатный TURN (Open Relay/metered.ca или Cloudflare TURN) в `iceServers` **с первого сетевого шага**. Без TURN на CGNAT не соединяется 10–20 % пар. Если соединения нет за 8 с, показываем «Не удалось подключиться, попробуйте Wi-Fi». Тип ICE-кандидата пишем в лог.
- **Почему не WebSocket-сервер.** Пользователь хочет обойтись без сервера; бесплатные хостинги засыпают (холодный старт 30–60 с); 6 игроков на 20 Гц хост-телефон тянет легко. Транспорт абстрагирован (`net/transport.js`: `send(ch,msg)`, `onMsg`, `onClose`). Запасной путь — WS-реле на Cloudflare Workers + Durable Objects без изменения логики игры.
- **Уход хоста (MVP).** Миграции нет. Хост держит экран через Wake Lock API, симуляцию гонит `setInterval`/Worker-тикер, а не rAF. Если от хоста 3 с нет пакетов или его вкладка скрыта дольше 5 с, клиенты видят «Хост вышел» с текущим счётом и кнопкой «Новая комната». Хост раз в 1 с рассылает `matchState` (очки, раунд, Избранный, порядок пиров): это задел под миграцию после MVP (следующий по списку регистрирует `izb-<КОД>-2`).
- **Уход клиента.** Персонаж удаляется. Если ушёл Избранный, сила переходит охотнику с наибольшим уроном за последние 5 с, а если такого нет — случайному.

## 2. Рендер: Canvas2D без движка
В сцене около 6 кругов, до 150 частиц и геометрия арены, ассетов нет. Phaser/Pixi добавили бы 300–1000 КБ и лишнюю абстракцию. Чистые ES-модули без сборщика, деплой на GitHub Pages как есть; PeerJS лежит в `lib/` с зафиксированной версией.

## 3. Неон без потери FPS
- `shadowBlur` в кадре не используется. Свечение (круг игрока каждого цвета, снаряд, частица) один раз рендерится в offscreen-canvas с blur 12–20, дальше только `drawImage`.
- `globalCompositeOperation='lighter'` — только для частиц и эффектов.
- Фон (сетка, стены, укрытия) рисуется один раз в отдельный offscreen-слой.
- DPR = `min(devicePixelRatio, 2)`. Если FPS < 50 держится 2 с, снижаем DPR до 1,5, затем до 1 и вдвое урезаем частицы.
- Пул частиц на 150, без аллокаций в кадре. Тряска экрана 4 px/150 мс, отключается.
- Палитра: фон `#07070f`, охотники циан `#3ef`, Пламя `#f60`, Молния `#ff3`, Лёд `#8ef`, Гигант `#f3f`.

## 4. Структура кода и цикл
```
index.html            // canvas + DOM-оверлеи (меню, лобби, итоги)
style.css
lib/peerjs.min.js     // фиксированная версия
src/main.js           // загрузка, экраны, цикл
src/config.js         // ВСЕ числа баланса и сети, iceServers
src/sim/world.js      // состояние, детерминированный step(state, inputs, dt), без DOM
src/sim/powers.js     // 4 силы: данные + функции
src/sim/combat.js     // хитбоксы, урон, смерть, передача силы
src/sim/match.js      // раунды, таймер, очки
src/net/transport.js  // обёртка PeerJS, каналы u/r
src/net/host.js       // приём ввода, снапшоты, matchState
src/net/client.js     // предсказание, интерполяция
src/render/renderer.js, glow.js, particles.js, hud.js
src/input/touch.js    // джойстик и кнопки (Pointer Events), клавиатура для ПК
```
**Цикл.** Симуляция работает на фиксированном тике **30 Гц** (dt = 33,3 мс) через аккумулятор. У хоста её гонит `setInterval`/Worker-тикер, чтобы она не вставала при просадках rAF. Рендер у всех идёт в `requestAnimationFrame` с интерполяцией alpha между тиками.

## 5. Синхронизация
- **Ввод:** клиент шлёт каждый тик (30 Гц) `{seq, dx, dy (int8), buttons (bitmask)}`. В пакет кладём **последние 3 тика**, чтобы переживать потери ненадёжного канала. Хост применяет каждый seq один раз.
- **Снапшоты:** 20 Гц, позиции int16, HP, состояние способностей, последний обработанный `seq` каждого игрока. Формат — JSON-массивы (меньше 1 КБ); на бинарный переходим, только если трафик станет проблемой.
- **Свой игрок:** предсказываем только движение и рывок. При расхождении меньше 40 px плавно подтягиваем за 100 мс, больше 40 px — телепорт. Переигрывания ввода нет.
- **Чужие игроки:** интерполяция с задержкой 100 мс по буферу из 3 снапшотов. Без пакетов экстраполируем до 150 мс, затем замираем.
- **Попадания** считает только хост, без отката. Компенсация задержки — щедрые хитбоксы (снаряды охотников +20 % радиуса) и телеграфы ≥300 мс: этого хватает при пинге до 150 мс.
- Звук и вспышку удара клиент проигрывает сразу, урон показывает по снапшоту.

## 6. Баланс (все числа в `config.js`)
Арена 1600×900 единиц, 4–6 колонн-укрытий, камера показывает около 1000×560 и следует за своим игроком. Радиус игрока 22, у Гиганта 40.

**Охотник:** HP 100, скорость 260 ед/с.
- **A «Выстрел»:** снаряд 700 ед/с, урон 8, КД 0,35 с, дальность 600, автонаведение на Избранного в конусе ±12°.
- **B «Рывок»:** 220 ед за 0,15 с, i-frames 0,2 с, КД 3 с.
- **Смерть:** респаун через 3 с у дальнего от Избранного края, затем 1 с неуязвимости.

**Избранный, база:** скорость 240, `HP = 250 × (N−1)`, где N — число игроков (500 при 3, 1250 при 6). Расчёт: DPS охотника ≈ 23, каждому охотнику нужно около 11 с чистого огня; при ~50 % промахов и уворотах Избранный живёт 25–40 с, это 2–3 смены силы за раунд. Реген 1 %/с, если 4 с не получал урона. Смена силы: добивший получает новую случайную силу и полное HP, плюс 1,5 с неуязвимости со вспышкой. Бывший Избранный становится охотником. При смерти от среды силу получает охотник с наибольшим уроном за последние 5 с.

| Сила | A (основная) | B (особая) | Пассив / слабость |
|---|---|---|---|
| **Пламя** | Огненный шар 30 урона, 500 ед/с, КД 0,6 с | Кольцо R=180, телеграф 0,4 с, 40 урона, КД 7 с | Лава 5 урона/с на 2 с. Шары медленные |
| **Молния** | Цепь 18 урона, +2 прыжка в R=250, КД 0,8 с | Телепорт 350 ед + разряд R=120 на 25 урона, КД 5 с | Скорость 300. HP ×0,8 |
| **Лёд** | Осколок 15 урона + замедление 40 % на 1,5 с, КД 0,5 с | Стена длиной 300 на 4 с, блокирует снаряды, КД 8 с | Малый урон, сильный контроль |
| **Гигант** | Конус 90° R=150, телеграф 0,3 с, 35 урона + отброс 200, КД 1,0 с | Прыжок, телеграф 0,5 с, R=200, 45 урона, КД 6 с | HP ×1,5, скорость 200, радиус 40: легко попасть |

**Масштабирование.** Урон Избранного не растёт, растёт только HP. При N ≥ 5 КД способности B снижается на 15 %, чтобы толпа не «запирала» Избранного.

**Очки:** добивание Избранного — 100. Каждые 10 урона по Избранному — 5. Секунда в роли Избранного — 2, но не больше 60 за одну жизнь в роли. Убийство охотника Избранным — 20. Если Избранный дожил до конца раунда — +50.
**Камбэк:** последний по очкам охотник наносит урон ×1,15 (видна иконка).
**Раунд:** отсчёт 3 с, затем таймер 90 с. В 1-м раунде Избранный случайный, дальше — последний по очкам. После 5 раундов — экран итогов: места, очки, «больше всего урона», «дольше всех Избранный», кнопка «Реванш» (тот же код).

## 7. Управление
- Плавающий джойстик в левой половине экрана (центр под пальцем, мёртвая зона 10 %).
- Справа кнопки A (84 px) и B (64 px), кулдаун показывается круговой заливкой.
- Прицеливание автоматическое: к ближайшей цели в направлении движения, у охотника приоритет — Избранный. Второй джойстик на телефоне перегружает управление.
- `touch-action:none`. Fullscreen и `screen.orientation.lock('landscape')` по тапу там, где они поддерживаются; на iOS — `100dvh`, `viewport-fit=cover` и оверлей «поверните телефон». Аудио только после первого тапа. Wake Lock во время матча.

## 8. MVP (7 шагов, каждый проверяется на телефоне)
1. **Каркас:** `index.html`, фиксированный тик, Canvas, арена с glow-кэшем, джойстик и кнопки, движение одного игрока, бот-мишень. Деплой на GitHub Pages с первого дня.
2. **Локальный бой:** выстрел с автонаведением, рывок, HP, Избранный с Пламенем, телеграфы, передача силы при добивании.
3. **Сеть:** PeerJS-комната по 5-символьному коду, **STUN+TURN сразу**, лобби на 3–6 игроков, старт у хоста, авторитетный хост с тикером на `setInterval`, снапшоты 20 Гц, интерполяция. Проверка с двух телефонов на 4G.
4. **Предсказание** своего движения (порог 40 px), избыточный ввод, обработка ухода клиента и хоста («Хост вышел», Wake Lock).
5. **Остальные 3 силы**, неоновые частицы, HUD.
6. **Матч:** раунды, таймер, очки, камбэк, экран итогов, реванш.
7. **Устойчивость и плейтест:** автоснижение DPR, отладочный оверлей (`?debug`: DPS, время жизни Избранного, тип ICE), плейтест на 3–6 телефонах. Цель — 60 FPS на среднем Android, время жизни Избранного 25–40 с. Правки только в `config.js`.

## 9. Риски
- **NAT/CGNAT:** TURN с шага 3. Если на тестах больше 10 % неудачных подключений — реле на Cloudflare Workers через тот же `transport.js`.
- **Брокер PeerJS недоступен или в лимите:** переключение конфигом на свой PeerServer.
- **Хост свернул вкладку или слабый телефон:** Worker-тикер, Wake Lock, честное завершение через 5 с. Миграция — после MVP, задел в `matchState` уже есть.
- **iOS Safari:** нет Fullscreen и orientation.lock, WebRTC в фоне рвётся — оверлей и подсказка «Добавить на экран Домой».
- **Читы хоста:** не решаем (игра среди друзей).
- **Баланс:** все числа в `config.js`, решения принимаем по метрикам отладочного оверлея.

Явно вне MVP: миграция хоста, lag compensation, переигрывание ввода, бинарный протокол, аккаунты, матчмейкинг.
