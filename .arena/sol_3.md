# «Избранный»: план реализации (сначала удовольствие от игры)

## 0. Что должно быть весело и честно
- **Читаемость.** За 0,3 с видно, кто Избранный: у него обводка в 1,6 раза крупнее, своя пульсирующая аура, а у края экрана стрелка-указатель. Каждой атаке предшествует телеграф: красный контур зоны поражения 300–500 мс.
- **Контригра.** У каждой силы есть окно уязвимости: откат после ульта, перегрев, медлительность. У охотника всегда есть рывок с i-frames, чтобы увернуться от телеграфа.
- **Камбэк.** Отставшим игрокам слегка помогаем: бонус «ассиста» и приоритет при спавне. Убивший Избранного получает силу, остальные охотники — очки за урон.
- **Короткие сессии.** Матч длится 5×90 с плюс паузы, всего около 9 минут. Вход по коду из 4 букв, без регистрации.

## 1. Сеть: P2P с авторитетным хостом (PeerJS) и миграцией хоста
- **PeerJS через бесплатный брокер 0.peerjs.com**, топология «звезда»: создатель комнаты становится хостом. ID пира хоста = `izb-` + код комнаты (4 символа A–Z без I/O). Соединение идёт как DataChannel с `reliable:false` (unordered) для ввода и снапшотов и отдельным reliable-каналом для событий (смерть, смена раунда).
- **NAT.** На мобильном интернете (CGNAT, симметричный NAT) примерно 10–20% соединений не устанавливаются без TURN. Подключаем STUN Google и бесплатный TURN (Open Relay от metered.ca или Cloudflare TURN на бесплатном лимите) в `iceServers`. Если за 8 с соединения нет, показываем «Не удалось подключиться, попробуйте Wi-Fi».
- **Почему не WebSocket-сервер.** Пользователь хочет обойтись без сервера, а 6 игроков и 20 Гц — ничтожная нагрузка для хоста-телефона. Запасной путь заложен в архитектуру: транспорт абстрагирован (`net/transport.js`), и при необходимости можно подставить сервер на Cloudflare Workers + Durable Objects, не меняя логику игры.
- **Уход хоста.** Хост каждые 2 с рассылает всем по reliable-каналу полное состояние матча (счёт, раунд, кто Избранный) и упорядоченный список пиров. Если хост пропал (нет пакетов 3 с), новым хостом становится следующий по списку: он регистрирует ID `izb-CODE-2`, остальные переподключаются к нему. Текущий раунд перезапускается с сохранённым счётом. Если хост свернул вкладку (`visibilitychange`), это считается уходом через 3 с.

## 2. Рендер: Canvas2D без движка
Фаза рисуется кодом, на экране не больше примерно 6 игроков и 200 частиц. Phaser и Pixi принесли бы 300–1000 КБ и лишнюю абстракцию. Хватает Canvas2D с ручным циклом, сборщики не нужны: чистые ES-модули, деплой на GitHub Pages как есть.

## 3. Неон без потери FPS
- **`shadowBlur` в кадре не используем**: на мобильных он работает медленно. Свечение спрайтов заранее рендерим в offscreen-canvas: круг игрока, рамка, частица. Каждый рисуется один раз с blur 12–20, потом выводится через `drawImage`.
- Наложение `globalCompositeOperation='lighter'` применяем только к частицам и эффектам.
- Фон (сетка арены) рисуем один раз в offscreen-слой.
- Разрешение: `devicePixelRatio`, ограниченный значением 2; при FPS < 50 в течение 2 с опускаем до 1,5, затем до 1.
- Лимит — 150 частиц, лишние переиспользуются из пула.
- Тряска экрана: 4 px на 150 мс, отключается в настройках.

## 4. Структура кода
```
index.html            // canvas, UI-оверлеи (лобби, итоги) в DOM
src/main.js           // загрузка, экраны, цикл
src/config.js         // ВСЕ числа баланса
src/sim/world.js      // состояние, step(dt) детерминированный
src/sim/powers.js     // 4 силы: способности как данные+функции
src/sim/combat.js     // хитбоксы, урон, смерть, передача силы
src/sim/match.js      // раунды, таймер, очки
src/net/transport.js  // PeerJS обёртка
src/net/host.js       // приём ввода, рассылка снапшотов, миграция
src/net/client.js     // предсказание, интерполяция
src/render/renderer.js, glow.js, particles.js, hud.js
src/input/touch.js    // джойстик + кнопки, клавиатура для ПК
```
**Игровой цикл.** Симуляция идёт с фиксированным тиком 30 Гц (dt=33,3 мс) через аккумулятор, рендер — по `requestAnimationFrame`, с интерполяцией между тиками (alpha).

## 5. Синхронизация
- Клиент отправляет ввод каждый тик (30 Гц): `{seq, dx, dy (int8), buttons (bitmask)}`, примерно 6 байт.
- Хост рассылает снапшоты на 20 Гц: позиции (int16), HP, состояние способностей, последний обработанный `seq` каждого игрока. Формат — JSON-массивы, при росте трафика переходим на бинарный.
- **Своего игрока клиент предсказывает** (только движение и рывок). При расхождении больше 4 px — плавная коррекция за 100 мс, больше 64 px — телепорт.
- **Чужих игроков** клиент рисует с интерполяцией: задержка 100 мс, буфер из 3 снапшотов.
- **Попадания определяет хост** по своему состоянию, без отката (rewind) — это сознательное упрощение. Компенсация — щедрые хитбоксы: у снарядов охотников радиус +20%. Телеграфы Избранного длятся ≥300 мс, их хватает на пинг до 150 мс.
- Звук и эффект попадания клиент проигрывает сразу при нажатии, а урон выводит по снапшоту.

## 6. Баланс
Арена 1600×900 условных единиц, камера показывает примерно 1000×560. Радиус игрока 22, у Гиганта — 40.

**Охотник (все одинаковые):** HP 100, скорость 260 ед/с.
- **Кнопка A, «Выстрел»:** снаряд 700 ед/с, урон 8, кулдаун 0,35 с, дальность 600; автонаведение на Избранного в конусе ±12°.
- **Кнопка B, «Рывок»:** 220 ед за 0,15 с, i-frames 0,2 с, кулдаун 3 с.
- **Смерть охотника:** респаун через 3 с у дальнего от Избранного края, 1 с неуязвимости.

**Избранный, база:** скорость 240, HP по формуле `HP = 250 × (N−1)`, где N — число игроков. Получается 250 при N=2, 500 при 3 и 1250 при 6. Логика: DPS одного охотника около 23 (8/0,35), значит каждый охотник «тратит» на Избранного примерно 11 с чистого огня. С учётом промахов (~50%) и уворотов Избранный живёт 25–40 с, то есть 2–3 смены силы за раунд.
- Получая урон, Избранный восстанавливает 0 HP. Пассивная регенерация — 1% в секунду, если урона не было 4 с: это наказывает охотников, которые отступили.
- **Смена силы:** добивший получает силу и полный HP, затем 1,5 с неуязвимости с яркой вспышкой. Если Избранный умер от окружения (лава, лёд), силу получает охотник, нанёсший больше всего урона за последние 5 с.

| Сила | A (основная) | B (особая) | Пассив / слабость |
|---|---|---|---|
| **Пламя** | Огненный шар: 30 урона, 500 ед/с, кулдаун 0,6 с | Огненное кольцо R=180: телеграф 0,4 с, 40 урона, кулдаун 7 с | Оставляет лаву (5 урона/с, 2 с). Слабость: шары медленные, от них легко увернуться |
| **Молния** | Цепная молния: 18 урона, перескакивает на 2 цели в радиусе 250, кулдаун 0,8 с | Телепорт на 350 ед с разрядом 25 урона R=120, кулдаун 5 с | Скорость 300. Слабость: HP ×0,8 |
| **Лёд** | Ледяной осколок: 15 урона + замедление 40% на 1,5 с, кулдаун 0,5 с | Ледяная стена (длина 300) на 4 с, блокирует снаряды, кулдаун 8 с | Слабость: малый урон; сила — контроль |
| **Гигант** | Удар по конусу 90°, R=150: телеграф 0,3 с, 35 урона + отбрасывание 200, кулдаун 1,0 с | Прыжок: телеграф круга 0,5 с, R=200, 45 урона, кулдаун 6 с | HP ×1,5, скорость 200, радиус 40 — в него легко попасть |

**Масштабирование от числа игроков.** Урон способностей Избранного не меняется, меняется только HP. При N ≥ 5 кулдаун особой способности (B) снижается на 15%, иначе толпа «запирает» Избранного.

**Очки:**
- Добивание Избранного — 100.
- Каждые 10 урона по Избранному — 5 очков (ассист).
- Секунда в роли Избранного — 2 очка, до 60 за жизнь в одной роли: так держать силу выгодно, но не бесконечно.
- Убийство охотника Избранным — 20.

**Камбэк.** Последний по очкам охотник наносит урон ×1,15, это видно по маленькой иконке. Если раунд закончился по таймеру с живым Избранным, тот получает бонус 50.

**Раунд.** Начинается со случайного Избранного: в первом раунде — случайный игрок, дальше — последний по очкам. Таймер 90 с. Перед раундом — отсчёт 3 с. Матч — 5 раундов, затем экран итогов: место, очки, «больше всего урона», «дольше всех Избранный», кнопка «Реванш» (тот же код комнаты).

## 7. Управление
- **Джойстик** плавающий, в левой половине экрана: центр там, где коснулся палец, мёртвая зона 10%.
- **Кнопки справа:** A — 84 px, B — 64 px. Кулдаун показывается заполнением по кругу.
- **Прицеливание автоматическое:** к ближайшей цели в направлении движения (для охотника — Избранный в приоритете). Второй джойстик на телефоне перегружает управление.
- Включаем `touch-action:none`, полноэкранный режим и запрос landscape. Если экран вертикальный — показываем экран «поверните телефон».

## 8. MVP (7 шагов)
1. Каркас: `index.html`, цикл с фиксированным тиком, Canvas, арена, джойстик и кнопки, движение одного игрока (локально, с ботом-мишенью).
2. Бой локально: выстрел, рывок, HP, Избранный с силой «Пламя», передача силы при добивании.
3. Сеть: PeerJS-комната по коду, лобби (3–6 игроков, старт у хоста), авторитетный хост, снапшоты на 20 Гц, интерполяция.
4. Предсказание своего движения, коррекция, обработка отключений.
5. Остальные 3 силы, телеграфы, неоновый glow-кэш, частицы.
6. Раунды, таймер, очки, камбэк-бонусы, экран итогов, реванш.
7. Миграция хоста, TURN, автоснижение DPR, деплой на GitHub Pages и плейтест на 3+ телефонах. Цель — 60 FPS на среднем Android и время жизни Избранного 25–40 с.

## 9. Риски
- **NAT и мобильные сети** → TURN и понятное сообщение об ошибке. Запасной путь — сервер на Cloudflare Workers.
- **Брокер PeerJS недоступен или в лимите** → переключаемся на собственный бесплатный PeerServer (Render/Fly) через конфиг.
- **Телефон хоста тормозит или свёрнут** → миграция хоста. Хостом выбираем игрока с лучшим пингом в лобби.
- **Читы хоста** — допустимый риск для игры с друзьями.
- **Баланс** → все числа в `config.js`, на хосте встроен отладочный оверлей с DPS и временем жизни Избранного. Подкручиваем после первого плейтеста.
