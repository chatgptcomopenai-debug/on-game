# «Избранный»: план с упором на сетевой код

Исходная точка: мобильная сеть. Какое решение ни выбери, оно должно пережить пять проблем, перечисленных ниже. Остальной план строится вокруг них.

## 0. Модель отказов → требования
| Отказ | Как проявляется | Требование к архитектуре |
|---|---|---|
| RTT 80–300 мс, джиттер ±80 | дёрганые враги, «я же попал» | клиентское предсказание своего игрока, интерполяция чужих с буфером 100–150 мс, попадания засчитывает хост с перемоткой (lag compensation) до 200 мс |
| Потеря 1–5 % пакетов, всплески | телепорты, потерянные нажатия | неупорядоченный ненадёжный канал для снапшотов; ввод отправляется избыточно (последние 3 тика в каждом пакете); события (смерть, смена Избранного) идут через надёжный канал с ack |
| Симметричный NAT / CGNAT у операторов | не удаётся соединиться (≈10–20 % пар) | обязательный TURN-фолбэк; топология «звезда», то есть каждый связан только с хостом |
| Хост ушёл / свернул вкладку | матч умирает | миграция хоста по детерминированному порядку и полный снапшот состояния у каждого клиента раз в 1 с |
| Вкладка в фоне | rAF стоит, таймеры троттлятся до 1 Гц, WebRTC живёт ~5 мин | хост в фоне через 3 с без heartbeat считается ушедшим → миграция; клиент в фоне превращается в бота, «стоит на месте» и неуязвим 3 с после возврата |

## 1. Сетевая архитектура
**Решение: P2P host-authoritative на WebRTC DataChannel (PeerJS), топология «звезда», плюс бесплатный TURN.**
- Хост — первый игрок в комнате. Симуляция идёт у него, клиенты шлют ему ввод.
- Код комнаты: 5 символов `[A-Z2-9]` без 0/O/1/I. PeerJS id хоста `izbr-<КОД>`. Сигналинг через бесплатный облачный PeerJS (0.peerjs.com).
- ICE: STUN Google плюс TURN (Open Relay Project/metered.ca, бесплатный тариф). Конфиг лежит в `net/ice.js`, чтобы его легко было заменить.
- Два DataChannel на пира: `u` (`ordered:false, maxRetransmits:0`) для ввода и снапшотов, `r` (reliable) для событий, лобби и чата.
- **Почему не WebSocket-сервер:** бесплатный сервер (Render, Fly) засыпает, к нему добавляется холодный старт и RTT до региона. P2P у игроков из одного города часто даёт меньший RTT. Запасной путь (риск №1, см. ниже): тот же протокол поверх WS-реле на Cloudflare Workers + Durable Objects (бесплатный тариф). Транспорт абстрагирован интерфейсом `Transport {send(ch,msg), onMsg, onClose}`.

**Миграция хоста.** У всех клиентов есть `peerOrder` (порядок входа). Хост раз в 1 с рассылает по `r` полный `FullState` (позиции, HP, очки, раунд, таймер, сила, сид RNG). Если 3 с нет пакетов от хоста (или пришёл `bye` при `pagehide`), следующий по `peerOrder` регистрирует id `izbr-<КОД>-m<N>` и остальные переподключаются к нему; N — номер эпохи. Новый хост восстанавливает мир из последнего `FullState` и экстраполирует таймер. Пауза 1–3 с, на экране надпись «Переподключение…». Если хост ушёл во время раунда, раунд продолжается, а Избранный остаётся Избранным.

**Видимость вкладки.** `visibilitychange` → `hidden`: клиент шлёт `away`, хост ставит его ввод на ноль. Если ушёл хост, он шлёт `bye` и `pagehide`, это запускает немедленную миграцию. Когда хост с вкладкой возвращается, он становится обычным клиентом.

## 2. Рендер
**Canvas2D, без движка.** Сцена простая (6 кругов-игроков, ≤150 частиц, геометрия арены), ассетов нет. Phaser/Pixi — это +300–1000 КБ и лишний слой. Неон без `shadowBlur` (на мобильных он дорогой):
- арену (сетку, стены со свечением) заранее рендерим в offscreen-canvas один раз;
- свечение = спрайт-кэш: для каждого цвета один раз рисуем радиальный градиент 64×64 и потом вызываем `drawImage` с `globalCompositeOperation='lighter'`;
- DPR ограничиваем до 2, логическое разрешение 960×540 с масштабированием под экран;
- частицы берём из пула (без аллокаций в кадре); если FPS < 50 в течение 2 с, качество понижается (частиц вдвое меньше, glow выключается).

## 3. Структура кода и цикл
Чистый ES-модульный JS без сборки (GitHub Pages напрямую), PeerJS с CDN.
```
index.html, style.css
src/main.js          — экраны: меню → лобби → игра → итоги
src/config.js        — все числа баланса
src/sim/world.js     — детерминированная симуляция step(state, inputs, dt)
src/sim/powers.js    — 4 сверхсилы
src/sim/collide.js   — круги, стены, лучи
src/net/transport.js — PeerJS-обёртка, каналы u/r
src/net/ice.js
src/net/host.js      — авторитетный цикл, снапшоты, lag comp, миграция
src/net/client.js    — предсказание, reconciliation, интерполяция
src/net/proto.js     — бинарная сериализация (DataView)
src/render/*.js      — arena, players, fx, hud
src/input/touch.js   — джойстик и кнопки, клавиатура для отладки
```
Цикл: фиксированный тик симуляции **30 Гц** (dt = 33,3 мс) через аккумулятор в rAF; рендер на частоте экрана с интерполяцией alpha. На хосте симуляцию дополнительно гонит `setInterval(33)` (MessageChannel-тикер), чтобы она не встала при просадках rAF.

## 4. Синхронизация
- **Ввод:** клиент шлёт каждый тик `{seq, ax, ay (int8), buttons (bits)}` вместе с двумя предыдущими, это 30 пакетов/с по ~12 байт.
- **Снапшоты:** хост шлёт **20 Гц** по `u`: `tick, lastAckSeq[peer]`, для каждого игрока `id, x,y (int16 ×10), vx,vy, hp (uint8), flags`, ≈ 6×14 + 10 ≈ 100 байт. Дельта-сжатие не нужно.
- **Свой игрок:** предсказание. Храним буфер ввода; при снапшоте откатываемся к позиции из сервера и переигрываем неподтверждённые ввод-тики. Ошибку < 30 px сглаживаем за 100 мс, большую — телепортом.
- **Чужие:** интерполяция с задержкой `renderDelay = 2 × 50 мс + jitter` (адаптивно 100–200 мс). Если пакетов нет, экстраполяция ≤ 150 мс, потом замираем.
- **Удары:** клиент мгновенно показывает эффект (косметика), урон засчитывает хост с перемоткой позиций целей на `RTT/2 + renderDelay` (максимум 200 мс), история хранит 8 снапшотов.
- **События** (`hit`, `kill`, `newChosen`, `roundEnd`) идут по `r` с номером и дедупликацией.
- **Часы:** пинг каждые 2 с, сглаженные RTT и offset; таймер раунда считается из серверного тика.

## 5. Геймдизайн и баланс
Арена 1600×900 логических px, 4–6 укрытий. Камера следит за своим игроком.

**Охотник:** HP 100, скорость 220 px/с, радиус 18.
- Кнопка A «Выстрел»: снаряд 600 px/с, урон 8, кд 0,4 с.
- Кнопка B «Рывок»: 180 px за 0,15 с, неуязвимость на это время, кд 4 с.

**Избранный (база):** радиус 26, скорость 240, HP = `250 + 200 × (N−1)`, где N — число охотников: 450 при 2, 1050 при 5. Пассивно реген 3 HP/с, если 3 с не получал урона. Урон охотников по Избранному ×1. Кнопки: A — атака силы, B — способность, C — ультимейт (заряжается за 30 с).

| Сила | A (атака) | B | C (ульта) | Особое |
|---|---|---|---|---|
| Пламя | конус 90°, 140 px, 30 урона/с поджог 2 с, кд 0,8 | огненный след 3 с, 15/с, кд 6 | взрыв R=220, 60 урона | — |
| Молния | луч 500 px, 22 урона, кд 0,7 | телепорт 260 px, кд 5 | цепь на 3 цели по 40 | скорость 270 |
| Лёд | осколок 700 px/с, 18 урона + замедление 40 % на 1,5 с, кд 0,6 | ледяная стена 3 с, кд 8 | заморозка R=200 на 1,5 с | — |
| Гигант | удар R=90, 35 урона + отталкивание 200, кд 1,0 | рывок-таран 300 px, 30 урона, кд 6 | 4 с ×0,5 получаемого урона, +50 % размер | HP ×1,3, скорость 200 |

Охотник умирает → респавн через 4 с в углу, дальнем от Избранного.

**Очки:** охотник +1 за 10 урона по Избранному, +50 за добивание. Избранный +2/с, пока жив, +30 за каждое убийство охотника. Добил Избранного → становишься им (полное HP по формуле, 2 с неуязвимости), бывший Избранный превращается в охотника. Раунд 90 с; в начале каждого раунда Избранный выбирается случайно среди тех, кто его ещё не был (сила тоже случайная). 5 раундов → экран итогов с местами и статистикой.

Цель баланса: Избранный выживает примерно 35–50 с. Метрика пишется в консоль, числа живут в `config.js` и подстраиваются после плейтестов.

## 6. MVP (7 пунктов)
1. Каркас: `index.html`, ландшафт (подсказка «поверните телефон»), фиксированный цикл, джойстик и кнопки, один круг бегает по арене. Неоновый рендер с glow-кэшем.
2. Транспорт: PeerJS + TURN, комната по коду, лобби до 6 игроков, каналы u/r, пинг. Проверка с двух телефонов на 4G.
3. Host-authoritative симуляция: ввод → снапшоты 20 Гц, интерполяция чужих, предсказание своего.
4. Бой: выстрел и рывок, HP, Избранный с одной силой (Пламя), lag compensation, передача роли при добивании.
5. Раунды 90 с, 5 раундов, очки, экран итогов.
6. Остальные 3 силы, ульта, масштабирование HP, полировка FX и HUD.
7. Живучесть: миграция хоста, обработка фона (`visibilitychange`/`pagehide`), переподключение клиента в течение 20 с по тому же нику, адаптивное качество.

## 7. Риски
- **TURN бесплатно ненадёжен / нет связи:** логировать тип ICE-кандидата; фолбэк на WS-реле Cloudflare (тот же `Transport`).
- **Облачный PeerJS-сигналинг падает:** нужен только на этапе входа; при необходимости поднимаем свой `peerjs-server` на бесплатном хостинге.
- **iOS Safari:** WebRTC в фоне рвётся сразу → миграция покрывает; полноэкранный режим недоступен, используем `viewport-fit=cover` и запрет жестов.
- **Читерство хоста:** вне scope MVP (игра среди друзей).
- **Батарея и нагрев:** 30 Гц симуляция, ограничение DPR, без shadowBlur.
