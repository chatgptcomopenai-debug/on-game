# «Избранный» — план (контрариан-ред-тим)

## 0. Дефолтный план (то, что предложит каждый)
1. PeerJS P2P, хост = рандомный игрок, full-mesh или star.
2. Phaser 3.
3. Тик 60 Гц, снапшоты 20 Гц, клиентское предсказание + реконсиляция.
4. Неон через `shadowBlur`.
5. Миграция хоста при уходе.
6. Избранный: x3 HP, плоский баланс.
7. MVP: сеть → движок → силы → UI.

Ниже атакую каждый пункт и оставляю только выжившее.

## 1. Сеть
**Атака на «PeerJS P2P».** Мобильный интернет = симметричный/CGNAT у операторов; без TURN 10–30% пар WebRTC не соединяются. Публичный PeerJS-брокер (0.peerjs.com) периодически лежит и не даёт TURN. Full-mesh для 6 игроков — 15 соединений, бессмысленно. Миграция хоста — самая дорогая и багоопасная фича; в MVP её делать нельзя.

**Атака на «WebSocket-сервер».** Бесплатные хостинги (Render free) засыпают, холодный старт 30–60 с; Fly/Koyeb требуют карту. Но: один авторитетный сервер решает NAT, уход хоста и читерство разом.

**Решение (выжило):** транспорт за интерфейсом `Net { send(msg), onMsg, onPeer }`, две реализации:
- **A (по умолчанию в MVP): PeerJS, star-топология, хост-авторитетный.** Хост = создатель комнаты (не рандом — так проще код комнаты: код = 5 символов, peerId = `izbr-<код>`). Клиенты подключаются только к хосту. В `config.iceServers` — STUN Google + бесплатный TURN (Open Relay / metered.ca free tier, ключ в конфиге). Канал `reliable:false, ordered:false` для снапшотов/ввода, отдельный reliable-канал для событий (смена Избранного, конец раунда).
- **B (запасной, шаг 7): Cloudflare Worker + Durable Object** как WebSocket-реле той же логики (бесплатный план, не засыпает, без карты). Хост-логика остаётся на клиенте-хосте, DO лишь пересылает — код игры не меняется.

**Уход хоста:** в MVP — НЕ мигрируем. Матч завершается экраном «хост вышел» с текущими очками. Каждые 1 с хост рассылает компактный `matchState` (очки, раунд, кто Избранный); миграция — пост-MVP: новый хост = минимальный peerId из оставшихся, создаёт `izbr-<код>-2`, остальные переподключаются. Уход клиента: его персонаж удаляется; если ушёл Избранный — сила случайному живому, раунд продолжается.

## 2. Рендер
**Атака на Phaser.** ~1 МБ, своя физика/сцены, которые нам не нужны (арена = круги и прямоугольники), WebGL-пост-эффекты glow на слабых Android проседают. **Атака на «Canvas2D + shadowBlur»:** `shadowBlur` — главный убийца FPS на мобилке (каждый вызов — гауссово размытие).

**Решение:** чистый **Canvas2D, без движка**, без сборщика (ES-модули, GitHub Pages напрямую). Неон без `shadowBlur` в кадре:
- **Pre-rendered glow sprites:** при старте рисуем каждый объект (круг игрока по цвету, снаряд, частица) один раз в offscreen-canvas с `shadowBlur`, затем `drawImage` — дёшево.
- `globalCompositeOperation='lighter'` для частиц/снарядов.
- Статический фон арены (сетка, стены) — отдельный canvas, рисуется один раз.
- DPR ограничен `min(devicePixelRatio, 2)`; если средний кадр > 20 мс 2 с подряд — DPR 1 и лимит частиц /2 (авто-качество).
- Лимит частиц: 200.

## 3. Структура и цикл
```
index.html          canvas, overlay-меню (DOM)
src/main.js         бут, экраны, rAF-цикл
src/net.js          Net-интерфейс, PeerJS-реализация
src/room.js         код комнаты, лобби, роли host/client
src/sim.js          детерминированная симуляция: step(state, inputs, dt)
src/powers.js       4 силы: данные + функции
src/balance.js      ВСЕ числа (единственный источник)
src/render.js       отрисовка, glow-кэш, камера
src/input.js        джойстик + кнопки (Pointer Events, multi-touch)
src/ui.js           HUD, итоги, лобби
src/interp.js       буфер снапшотов, интерполяция
```
**Тик:** симуляция 30 Гц (не 60 — атака: на мобилке хост тоже телефон, 60 Гц × 6 игроков удваивает CPU и трафик без видимого выигрыша для аркады). Фиксированный шаг с аккумулятором, рендер на rAF. `sim.js` чистый, без DOM — запускается только у хоста.

## 4. Синхронизация
**Атака на «предсказание + реконсиляция».** Это 40% сложности сетевого кода. Для top-down аркады с RTT 60–150 мс заметна только задержка своего движения.

**Решение:**
- Ввод клиента: 30 Гц, `{seq, dx, dy (int8), buttons (bitmask)}` ~6 байт; хост берёт последний.
- Снапшоты: **15 Гц**, бинарно (`ArrayBuffer`, позиции int16, ~12 байт/игрок) — укладывается в любой 3G.
- Чужие объекты: интерполяция с задержкой 100 мс.
- Свой персонаж: **только движение** предсказываем (простая кинематика без коллизий с игроками), при расхождении > 1.5 ед. — плавное подтягивание 20%/кадр. Способности НЕ предсказываем: мгновенный локальный VFX-«вспышка» для ощущения отклика, урон — по хосту.
- Хит-проверки на хосте без lag-compensation (снаряды медленные, хит-боксы щедрые +15%).

## 5. Баланс
Арена 1600×900 ед., препятствия-колонны (укрытие охотникам). N — число игроков, H = N−1 охотников.

**Атака на «x3 HP».** Плоский множитель ломается между 3 и 6 игроками. Масштабируем от H.

| Параметр | Охотник | Избранный |
|---|---|---|
| HP | 100 | 150 + 110·H |
| Скорость | 220 ед/с | 200 (Гигант 160) |
| Атака (кн. A) | выстрел 12 урона, 0.4 с КД, скорость 600 | см. силы |
| Рывок (кн. B) | 250 ед, КД 4 с, 0.2 с неуязв. | то же |
| Респаун | 3 с, в дальней от Избранного точке | — |

Охотник DPS ≈ 30 → при 5 охотниках Избранный с 700 HP живёт ~5 с под фокусом, реально 20–40 с с учётом уклонений. Регенерация Избранного: 0 (иначе раунды затягиваются).

**Силы (A — основная, C — ульта):**
- **Пламя:** A — конус 90°, 160 ед., 50 DPS (тик 0.1 с), поджог 10/с 2 с. C — огненное кольцо R 220, 60 урона, КД 10 с.
- **Молния:** A — мгновенный луч 500 ед., 28 урона, КД 0.5 с. C — блинк 350 ед. + цепь на 3 ближайших по 30, КД 8 с.
- **Лёд:** A — осколок 22 урона + замедление 40% 1.5 с, КД 0.35 с. C — заморозка зоны R 180 на 1.2 с (стан), КД 12 с.
- **Гигант:** размер x1.8, HP ×1.3, урон по нему −20%. A — удар 120 ед. дуга 120°, 40 урона + отталкивание, КД 0.8 с. C — прыжок-удар R 200, 50 урона, стан 0.8 с, КД 9 с.

Контрариан-правки: стан ≤1.2 с (на телефоне стан ощущается дольше); никаких «ваншотов».

**Очки:** охотник: 1 за каждые 10% HP урона по Избранному, 10 за добивание. Избранный: 1/с живым, 5 за убийство охотника. Если раунд истёк — Избранный +15. Добивший становится Избранным (новая случайная сила, полное HP), остальные мгновенно лечатся; если урон от среды/нет добившего — случайный охотник. Раунд 90 с, 5 раундов; в начале каждого раунда Избранный — лидер по нанесённому урону прошлого раунда? — **нет** (атака: снежный ком), — случайный, кто ещё не был Избранным в матче.

## 6. Ввод
Pointer Events, джойстик динамический (появляется под пальцем в левой половине), кнопки A (большая), B, C справа. `touch-action:none`, блок жестов. Ориентация: `screen.orientation.lock('landscape')` после фуллскрина, иначе оверлей «поверните телефон». Wake Lock API во время матча.

## 7. MVP (7 шагов)
1. Офлайн-арена: Canvas2D, glow-кэш, джойстик/кнопки, движение и стрельба одного игрока, фикс. тик.
2. `sim.js` с ботами-манекенами: Избранный с одной силой (Молния), HP, урон, смерть, передача роли.
3. PeerJS star: код комнаты, лобби, хост-симуляция, ввод→снапшоты 15 Гц, интерполяция.
4. Предсказание своего движения + бинарные снапшоты; тест на реальном 4G с двух телефонов.
5. Остальные 3 силы + баланс-таблица в `balance.js`.
6. Раунды/матч/очки/экран итогов, обработка ухода игроков.
7. TURN-конфиг + авто-качество; запасной CF Worker-реле, если на тестах >10% неудачных коннектов.

## 8. Риски
- **NAT/CGNAT** → TURN с первого дня, реле CF как план Б.
- **Хост на слабом телефоне/свернул вкладку** → вкладка в фоне останавливает rAF: симуляцию хоста гнать через `setInterval` + Worker-таймер; при `visibilitychange` hidden >5 с — конец матча.
- **Падение брокера PeerJS** → свой PeerServer на том же CF не нужен; переход на реле B.
- **Баланс** → все числа в `balance.js`, оверлей отладки с URL-параметром `?debug`.
- **iOS Safari** → нет orientation.lock: CSS-поворот невозможен корректно, только оверлей.
